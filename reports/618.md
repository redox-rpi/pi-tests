## Finding: the child dies with an exception at PC 0

Each failed 2 GiB fork logs one `UNHANDLED EXCEPTION` for the child (parent PID 384 → child **385**, parent 400 → child **401**), name `/usr/bin/oomtest` ([serial.log](618/serial.log)):

```
FP …: PC 0000000082000004
0000000000000000: GUARD PAGE
kernel::context::signal:INFO -- UNHANDLED EXCEPTION, CPU #1, PID 385, NAME /usr/bin/oomtest, …
kernel::arch::aarch64::interrupt::exception:ERROR -- FATAL: Not an SVC induced synchronous exception (ty=100000)
ELR_EL1: 0000000000000000 … all registers 0
```

So the half-made child is not torn down. It is scheduled with empty registers, jumps to address 0 and is killed by the exception. Test 617's image did not have this (UNHANDLED 0), but there the child stayed. The result is right (no leftover, the parent gets ENOMEM), but each failed fork prints about 50 lines of exception dump. A tool that counts `UNHANDLED EXCEPTION` as a failure (soaks, the crash checks) would count it. The row did not ask about this; Architect can say whether it is expected.
