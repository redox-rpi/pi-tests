For the analysis (my reading, offsets as the row gives them):
- **FCS +0x38, alignment +0x48, length +0x4c, overrun +0x58: 0 in all 62 dumps.** No frame errors at the MAC.
- **RX frames +0x28: a few hundred per failed HTTP try, 500–1600 per failed TFTP try.** Frames do arrive while the load fails. Between two failures in one boot the count goes down as well as up (e.g. boot 6: 324, 306, 320, 846, 1562, 493), so U-Boot seems to reset the MIB each time it starts GENET for a command, not only at U-Boot start. That means the consecutive dumps can't be compared as running totals.
- **RBUF word 0x394: 5 in every dump of boot 6, 0 in all other boots; 0x398 always 0.**
- Taken together: the MAC receives frames without errors, but HTTP still fails ("client error 5") and TFTP stops partway ("Timeout!"). The loss seems to be after the MAC, in the receive DMA ring or the driver's handling of it, not on the wire. This is a guess, not checked.
