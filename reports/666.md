# Test 666 – Pi 400, xHCI command ring wrap with No Op commands, then the power trigger (#749)

Date: 2026-11-25, 17:42–17:51 UTC. Pi test agent, no person. Pi 400, network boot, the USB mouse in port 1.1, the keyboard on 1.4. config.txt unchanged. Both images match the row's sha256:
- **A** (control, 256-entry ring): `keep/ut8n-netboot/` `v0.7.0-dev-65-ge0bf8af5+x0aa4`, img.gz `0e119cc4…`
- **B** (0027 + 0028, 128-entry ring with zeroed memory behind it): `keep/ut8-netboot/` `v0.7.0-dev-66-gf8bc952d+x0aa4`, img.gz `f8a6359e…`

The triggers were typed on serial as root.

Result: **fail.** B hangs at the first wrap of its command ring, just like control A:
- A sends 200 No Ops, then the ring wraps (`256 → 1/256 cycle 0`). xhcid logs **255** × `Lost event TRB type 33, completion code: 5`.
- B prints no progress line. Its ring wraps (`128 → 1/128 cycle 0`), and xhcid logs **127** × `Lost event`.
- Neither prints the summary line.
- After the wrap in B, the three power triggers get no reaction: no kill, attach or trace lines.
- No panic, no reset.

## (1) Image A, `echo 1000 > /tmp/xhcid-noop` (boot time 01:21)

- `usb-trace: sending 1000 no-op commands`
- `no-op 100 done, cmd_ring 119 cycle 1`
- `no-op 200 done, cmd_ring 219 cycle 1`
- No summary line, no further progress.
- **01:21.438 – 01:27.830: 255 × `Lost event TRB type 33, completion code: 5`.**
  - The first event's data is `…1B27000`, the start of the command ring. The data rises by 0x10 per event, up to `…1B27FE0` (entry 254). The control field changes from `00008400` to `00008401` along the way.
  - So after the wrap the controller works through every old ring entry once more, and each gives TRB error (completion 5).
- Resources: `commands 19 cmd_ring 19/256 cycle 1` before, **`commands 256 cmd_ring 1/256 cycle 0 workers 3 handles 16 ports 3`** after (one line). The last trace line is at 01:23.
