## Boot time (direct SD boot, first measurement)

| Stage | Boot 1 (12:53) | Boot 2 (12:59) |
|---|---|---|
| `kreset` to `rpi-boot-stub` (firmware) | 17.0 s | 17.0 s |
| stub to kernel start | 0.6 s | 0.6 s |
| kernel start to banner | 8.6 s | 8.7 s |
| banner to `redox login:` + chime | 1.9 s | 2.9 s |
| **kernel start to login** | **10.5 s** | **11.6 s** |
| **`reboot` to login** | **28.1 s** | **29.2 s** |

Kernel start to login matches the estimate (10-11 s against 20.4-20.9 s over the network, row 215). The 17 s firmware stage is steady; the likely cause is the firmware reading the whole system (~222 MiB RAM disk) from the card. Not confirmed yet: `uart_2ndstage=1` in config.txt would show the firmware's own load times. USB device detection is the largest part of the kernel stage (4.7 s).

## Notes for v0.6

1. `kstop` is printed only on the serial console. A user without a cable can't see when to pull the power: show a line on the screen.
2. After `kstop`: `PSCI SYSTEM_OFF failed: Unavailable` (no PSCI without U-Boot), and parts of the system keep running (`netstack-watch: main loop stuck …` 5 s and 35 s later). The audio outputs were already at 0 V, so pulling the power is safe.
3. The firmware stage (17 s) makes a direct reboot slower in total than the kernel stage suggests: a smaller RAM disk or reading the system from the card would be the lever.
