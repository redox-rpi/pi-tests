# Test 572 – DHCP only on an Ethernet adapter with a link (#560, PR #614), Pi 3B+

Result: **pass** (part A link and DHCP with the cable in; part B no DHCP without a cable, lease on plug-in and replug). The timesync check of part A could not run (not in that image); part B had timesync.

## Part A – cable in (no person)

Date: 2026-11-22, 14:45–14:51 UTC. Pi test agent. Image `~/zrtl-q/link560-stage/` (`sha256sum -c SHA256SUMS` OK), build `v0.6.0-dev-134-gc00603a8+x42c6`, experiments `netstack-watch` only.

Result A: **pass for the link and DHCP. The timesync check could not run, because timesync is not in this image.**

- The first boot came up with an empty USB root port (`nothing on the root port`, #576). This image does not have the `usb-port-power` experiment, so it lacks the #576 fix. One serial reset brought the network up. The checks below are from that boot.
- Serial: `dwc2d: link up on the LAN7800 at address 3`, then **`DHCP: eth0 got <lan-ip>/24`** and **`DHCP: default route via <router> (eth0)`**, as before ✔.
- Over devsh ([A-devsh.txt](572/A-devsh.txt)):
  - `cat /scheme/netcfg/ifaces/eth0/link` → **`1`** ✔
  - `cat /scheme/network.usb_lan78xx/link` → **`1`** ✔
  - `cat /scheme/netcfg/route/list` → `default via <router> dev eth0 …` ✔
- **timesync: not checked.** The image was built with only the `netstack-watch` experiment, so it has no timesync: there is no `timesync:` line at all, and `date` showed `Thu Jan 1 00:01:14 UTC 1970`. To check "timesync sets the clock" and "timesync is quiet without a network" (part B), the image needs the `timesync` experiment.
- **Error lines compared with the stable boot right after** (`v0.6.0-dev-126-g1b6b4cd9+x2d42`, same Pi): the only extra line is `procmgr: State Id(9) was placeholder!` (WARN). That line is not new: it shows up in 30 of the 100 rc2 boots of Test 570 too. `RELIBC PANIC` 0, `UNHANDLED EXCEPTION` 0.

Afterwards: stable staged and booted, devsh up (14:50).
