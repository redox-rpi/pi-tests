### Errors after the address step, whole

```
1970-01-01T00-01-28.056Z [@xhcid::xhci::scheme:2852 ERROR] CONFIGURE_ENDPOINT command (TRB Trb { data: 0000000006774000, status: 00000000, control: 02003001 }) failed with event trb Trb { data: 0000000003184090, status: 11000000, control: 02008401 }
1970-01-01T00-01-28.148Z [@xhcid::xhci::scheme:2865 ERROR] CONTROL_TRANSFER transfer Trb { data: 0000000000000000, status: 00000000, control: 00011020 } failed with event Trb { data: 0000000006775040, status: 06000000, control: 02018001 }
```

Decoded with the xHCI spec (my reading, please check):
- CONFIGURE_ENDPOINT: command TRB type 12 for slot 2; the completion event (type 33) has code 0x11 = **Parameter Error**, so the xHC rejected something in the input context. Its timing (between interface 1's start at 27.979 and interface 0's at 28.035) suggests it is the endpoint 0x82 setup for interface 1. A guess: for a low-speed interrupt endpoint behind a high-speed hub the interval, max packet size or the TT fields in the slot context may not be what the VL805 accepts.
- CONTROL_TRANSFER: a Status-stage TRB (type 4, IN) on slot 2, endpoint 1 (EP0); the transfer event has code 6 = **Stall**. That is the keyboard (or the hub's TT) refusing a request on interface 0. It comes right after interface 0 picked endpoint 0x81, so maybe a HID class request such as SET_IDLE or SET_PROTOCOL. Some keyboards stall SET_IDLE, and drivers normally ignore that.

Later on the console: `[@inputd:275 ERROR] invalid path ''` at 00:02:29.
