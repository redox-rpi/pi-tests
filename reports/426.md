### B: pi-test over devsh (not possible) and serial checks instead

- **devsh:** port 2323 gives `Connection refused`. The network is up, but the rc1 SD card image has no devshd, which is right for a release card. So **pi-test could not run**. Instead I logged in on the serial console as root.
- `/etc/redox-rpi-release`: `RELEASE="v0.5.0-rc1"`, `IMAGE="sdcard"`, `BUILD_ID="v0.5.0-dev-214-g600bd997+x59bc"`.
- `/scheme/rpi-firmware/arm_clock`: `1200000000`. Our firmware sets 1200 MHz (`mbox:arm: clock 1200 MHz set (ndiv 62 frac 80000 div 1) … now 1200000 kHz`), and the governor also went down to 600 MHz.
- `free`: total 957492 KiB, used 121256 KiB.
- **`mbox: alive` lines:** 3 per boot, e.g. `mbox: alive 10 s, 9 requests, ARM->VPU 40000000 VPU->ARM 40000000`, and later `alive 30 s, 100 requests`.
- **`/scheme/data` is missing:** `ls /scheme/data` gives `No such device`. In the boot, `bcm2835-sdhostd` sees the card (`SDHC/SDXC card, 30436 MiB, 4-bit bus, high speed, up to 49 MHz`, `serving /scheme/disk.mmc`), but then `[ERROR redoxfs] failed to open filesystem /scheme/disk.mmc/0: No such file or directory`, and the same for `…/0p0`. So pi-test's sdcard check would fail on this card. Redox itself runs from the RedoxFS that U-Boot loaded (`RedoxFS fd97e0ee…: 990 MiB`, `REDOXFS_BLOCK=0`). I can't tell from here whether the plain rc1 SD card has the same gap or only this card's layout does.
- `startup-sound: played`.

## Notes

1. **The firmware's mailbox trace goes to the same serial line as the Redox console.** Lines like `mbox: 00030020?`, `mbox: 00030046` and `mbox: 00038002` appear in the middle of what is typed at the shell, so the console is hard to read and to script. Does a release build need these trace lines, or should they be off unless the debug build is used?
2. `mbox: 00030020?`, with the question mark, appears to be a tag our firmware doesn't know. It comes again with each `cat` and `ls`.
3. Row design: a release SD card has no devsh, so pi-test can't run on it. A later row could use a netboot image on top of our firmware, or pi-test over the serial console.

The last 50 serial lines of boot 3 are in `~/pitest-tools/t426/last50.txt` on the build host.

**The Pi 3B+ is still running from this card. The user needs to swap the selector card back in before the nightly at 03:15 UTC.**
