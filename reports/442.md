### The new panic

```
[@usbhubd:133 INFO] attach port 1.4 at xHCI speed 2
[@xhcid::xhci:858 INFO] port 1.4: speed 2 from its hub (root port speed 3)
thread 'main' (1) panicked at drivers/usb/xhcid/src/xhci/mod.rs:893:18:
Failed to retrieve speed ID
[ERROR xhcid@src/header/stdlib/mod.rs:121] Abort
kernel::arch::aarch64::interrupt::exception:ERROR -- FATAL: Not an SVC induced synchronous exception (ty=111100)
ESR_EL1: 00000000F2000001
kernel::context::signal:INFO -- UNHANDLED EXCEPTION, CPU #1, PID 26, NAME /usr/lib/drivers/xhcid
```

This is a Rust abort (BRK, ESR F2000001), not #332. The script's "#332 fault" count of 1 is this line.

In the 0012 tree (`work/base-ss` in the audio clone) line 893 is `self.lookup_psiv(port_id, speed).expect("Failed to retrieve speed ID")`. `lookup_psiv` only searches the explicit speed entries (PSI) of the root port's Supported Protocol capability for the value 2. A guess, not checked on the Pi: the VL805 gives no explicit entries for its USB 2 ports (PSIC 0), and then the xHCI default IDs apply (1 full, 2 low, 3 high, 4 super), which the lookup does not know. In row 439 (before 0012) xhcid got past this line with the root port's speed 3 and failed later, at address device. Logging the PSI count of port 1's protocol would settle it.
