# 547: V3D step 0 on the Pi 400 (`v3dprobe`)

**Result: fail, safely.** v3dprobe stops before touching V3D: `FAIL: GRAFX has no power (the firmware did not power it): not touching V3D`. No panic, no exception, the Pi kept answering, and the display still runs.

- Pi 400, network boot, no person. 2026-11-20, 16:29–16:33 UTC.
- Image `keep/gfx-v3dprobe-netboot/` (img.gz `d2425f8c…`, manifest `46b2af7d…`), banner `v0.6.0-dev-166-g7808c378+xc358 (netboot)`. U-Boot's TFTP load failed twice before the boot went through (#394).
- config.txt as Test 546: `total_mem=1024` removed, `hdmi_force_hotplug=1` and `hdmi_drive=2` added.

## What v3dprobe read (same in all three runs)

| Step | Value |
|---|---|
| devicetree | `v3d@7ec04000 (brcm,2711-v3d)`, **status disabled** |
| clock v3d | 250 MHz (max 500) |
| `PM_GRAFX` (pm 0x10c) | `0x00001000`: power up false, power ok false, V3D reset asserted |
| `ASB_AXI_BRDG_ID` | `0x62726467` = **"brdg"** (as expected) |
| `ASB_V3D_M_CTRL` / `S_CTRL` | `0x00000007` / `0x00000007` |
| result | `FAIL: GRAFX has no power` |

- `v3dprobe --off` printed the same and the same FAIL; the second `v3dprobe` too.
- `vc4shot /tmp/s.ppm`: works, channel 1 640x480, 1 plane, 921615 bytes.
- After the probes devsh still answers. Serial: 0 lines with `panic` or `UNHANDLED`.
