# Test 586 – Tux Typing as a package: `pkg-persist install tuxtype` (PR #534, #529), Pi 3B+

Date: 2026-11-23, 19:25–19:47 UTC. Pi test agent, no person. Image `~/redox-rpi-audio/keep/tuxtype-pkg-stage/` (harddrive.img.gz `bd631e17…`, manifest `0037539b…`, both checked), build `v0.7.0-dev-31-gbaf813ee+x2ff5`. Two runs; the second one, with `df`, is the one reported.

Result: **fail.** `pkg-persist install tuxtype` stops after 2 min 23 s with `No space left on device (os error 28)`. The space that runs out is the **root file system in RAM (`/`, 222 MB), not the data partition on the card.** So steps 3–5 have nothing to check.

- pkg lists 14 packages: `Download size: 64.8 MB`, `Install size: 64.8 MB`. All 14 downloads finish (the last is `zlib.pkgar`), then the install fails and pkg rolls back (`Transaction aborted successfully`).
- 64.8 MB does not fit in the 46 MB left on `/` of this desktop image. The download, or the unpack, goes to `/` and not only to `/scheme/data/pkg`. `df` does not list the data partition, so I could not see how full it was.
- After the abort, `/` stays full (28 KB free), so pkg does not free its downloads after the rollback. A reboot clears it, since `/` is in RAM.
- `/scheme/data/pkg` was created (it is in `ls /scheme/data` afterwards), but it holds no tuxtype files.
