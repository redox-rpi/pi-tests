# 499: Pi 400 Ethernet speed A/B with `genet-coalesce`, and the ifconfig MAC (#540, REQ-NET-8 criteria 3 and 5)

**Result: C3 fail, C5 pass.**
- **Speed:** B is about 15 % faster than A (14.7 against 12.5 MB/s with ncnull), but stays under the 20 MB/s the row asks for. Both SHA-256 checks are right on A and B.
- **Ping:** B's average is 0.16 ms above A's (the limit is 0.5 ms).
- **ifconfig (C5):** shows the right MAC on both images.
- No panic, no `main loop stuck`.

The numbers point at **netstack, not the interrupts, as the limit**: B has 39 % fewer GENET interrupts and 16 % less CPU time in both drivers, but netstack still uses about 4.4 s of CPU per 7.1 s transfer.

- Only IRQ 189 and IRQ 27 changed.
- **IRQ 189:**
  - 100 MiB is about 72 000 full frames. A takes about 1.4 interrupts per frame.
  - B still takes about 0.87 per frame, so most frames still get their own interrupt.
  - At about 12 000 frames/s a frame comes every 80–90 µs, so the 100 µs timer fires before 16 frames have arrived.
- **`nc`:** not in the table, because it has exited before the snapshot after each run; its CPU time is gone from `/scheme/sys/context`.
- **Idle:** the idle contexts (`[kmain]` on CPUs 0–3) show ACTTIME 0 in every snapshot, so this kernel does not count idle time there.
- **Other contexts:** the next biggest per run were usbhidd 0.9–1.5 s, xhcid about 0.3 s and redoxfs about 0.25 s, the same in A and B.
