# 541: Pi 400 with all 4 GiB and a 256 MiB DMA zone (#299, PR #580)

**Result: the 256 MiB zone works.**
- The kernel prints **`DMA zone: 262144 KiB below 0x40000000 for DMA buffers (RAM up to 0xfc000000)`**.
- `free` shows **388796 KiB used**, against 192244 KiB with the 64 MiB zone (Test 536 B). That is about 192 MiB more, as expected for the 192 MiB larger zone.
- GENET works: `link up, Mbit1000`, DHCP and devsh. pi-test tcp moved 10 MiB at 3.6 MiB/s with the right SHA-256. 300 starts, 0 failed.
- rpi-fbd works: 640x480, double buffered, CPU blits. `fbshot` shows the console (`640x480, top colour 98%, 2 colours`).
- No panic, no `UNHANDLED`.
- The other pi-test FAILs are the known ones from Test 535:
  - `sdcard` (no card);
  - `audio` (no audiod);
  - `time` (NTP);
  - `reboot` (U-Boot TFTP #394). After pi-test's reboot the Pi 400 sat at U-Boot, and `boot` brought it back on the second try.

- Pi 400, network boot from `/srv/tftp/pi400/`, no person, no power cycle. 2026-11-20, 13:20–13:32 UTC.
- Image `~/redox-rpi-pi400/keep/genet-4g-mem256-stage/`: `sha256sum -c SHA256SUMS` all OK. Build `v0.6.0-dev-130-gfc036121+x6a0a`.
- **config.txt:** `total_mem=1024` removed, `hdmi_force_hotplug=1` and `hdmi_drive=2` added (as Test 536). Afterwards restored (`diff` same).
- U-Boot's TFTP load failed twice per boot (#394), and `boot` was typed each time.
