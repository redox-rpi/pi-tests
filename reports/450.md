# Test 450 – v0.6.0 must criteria on rc1: 100 boots, 1 hour idle, 1000 connections (Pi 3B+)

Date: 2026-11-21 18:59 to 2026-11-22 00:18 UTC. Pi test agent. Build ID `v0.6.0-dev-125-g5acacd83+xc80e` (rc1 network boot test build, `~/redox-rpi-rel/keep/v0.6.0-rc1-netboot.img`, the same one as Test 474). Row 458 ran first in the same boot.

Result: **fail, two of three parts.**

| Part | Criterion | Result |
|---|---|---|
| A | REQ-NET-1 crit 3: 100 of 100 boots with network within 60 s | **fail: 66/100** (the USB warm-reboot fault #576) |
| B | REQ-NET-1 crit 4: 1 hour idle | **pass** |
| C | REQ-NET-4 crit 2: 1000 short connections | **fail: memory grows** (connection 1001 works) |

`netstack-watch` is not in this build (not in `ps`, no line in the serial log), so its checks in A and B could not apply.

## A – 100 resets

- Each reset was `echo reset > /scheme/sys/kstop` over devsh. The time runs until `/scheme/netcfg/ifaces/eth0/addr/list`, read over devsh, shows the Pi's address. So devsh answered too.
- **66 boots had network within 60 s, all in 39.0–42.3 s (nearly all 41 s).** 34 had no network at all ([A-times.txt](450/A-times.txt)).
- All 34 failures are the USB warm-reboot fault #576. dwc2d never attached the LAN7800, so dhcpd got no offer:

| Kind | Boots | Count |
|---|---|---|
| `nothing on the root port` (empty port) | 1, 5, 16, 19, 23, 24, 28, 29, 33, 36, 39, 41, 43, 44, 45, 49, 50, 57, 58, 62, 69, 70, 72, 73, 86, 87, 88, 93, 97, 99, 100 | 31 |
| `device on root port, Full speed` (6×), then enumeration failed | 13, 14 | 2 |
| no dwc2d line in the kept section, only `dhcpd: no offer` | 6 (the reset right after the power cycle) | 1 |

- After a failure, the Pi was brought back with a serial reset: 40 serial resets in total. Once (after boot 5, two serial resets also came up empty) with **1 power cycle**, counted apart.
- This is the known fault: stable has it, and v3 of #576 (Test 568, 30/30) fixes it. v3 is not in rc1. With #576 v3 in rc2, this part should be run again.
- No `RELIBC PANIC`, no `UNHANDLED EXCEPTION`, no `main loop stuck` in the whole run.
- The serial sections of the failed boots are in [A-fail-logs.txt.gz](450/A-fail-logs.txt.gz).

## B – 1 hour idle

- After a fresh reset, the Pi sat idle from 19:45:56 to 20:45:58, with no devsh session.
- Afterwards the address was still there (`<lan-ip>/24`, [B-after.txt](450/B-after.txt)), and **a new devsh connection was accepted**.
- The serial log has **0** `main loop stuck` and **0** `no timer event` (but see the `netstack-watch` note above: nothing would have printed those lines).

## C – 1000 short connections

- 1000 devsh connections in a row from the build host, each running `echo cN` and closing. **0 failed. Connection 1001 worked.**
- Measured twice at rest, then after 500 and after 1000 (`ps`, `free`, `/scheme/sys/iostat`):

| | rest 1 | rest 2 | after 500 | after 1000 |
|---|---|---|---|---|
| `free` used | 140372 KB | 140724 KB | 310988 KB | **440452 KB** |
| netstack PRIVATE | 5.23 MB | 5.23 MB | 5.48 MB | **5.73 MB** |
| devshd PRIVATE | 11.2 MB | 11.3 MB | 35.5 MB | **45.8 MB** |
| netstack open files (iostat) | 28 | 28 | 28 | 28 |
| devshd open files (iostat) | 40 | 40 | 105 | 78 |

- Rest noise: `free` +352 KB, netstack 0, devshd 0.1 MB.
- **From 500 to 1000:** `free` used +129 MB, netstack +0.25 MB, devshd +10 MB. All of these are far above the noise, so **fail**.
- netstack grows slowly (about 0.5 KB per connection). Its open files stay at 28, so it does not keep sockets as open files.
- devshd grows more. Most of the growth in `free` (about 300 MB over 1000 connections, about 300 KB each) is in **no process's PRIVATE**: the other processes in `ps` stay the same, so it is probably kernel memory. That is a note for the Network owner (#88) and the kernel.
- No measure counts netstack's sockets directly; that is a follow-up for the Network owner (#88), as the row says.
