# 531: Pi 400 with all 4 GiB, without `total_mem=1024` (#299)

**Result: nothing in this image breaks with all 4 GiB.**
- U-Boot says `DRAM: 3.9 GiB`.
- The kernel maps memory up to 0xFC000000, and `free` shows **3757152 KiB total, 122124 used**.
- The boot reaches `redox login:` with no panic and no new error line.
- USB through the VL805 (xhcid) works: the internal keyboard is set up.
- Every line on the list is the same as in the restored 1 GiB boot right after it.

**Not covered:** this image (row 501's) has **no network driver** (bcmgenet), so there was no devsh and no pi-test.
- There is no monitor on the Pi 400, so rpi-fbd has no framebuffer, in both boots.
- So GENET DMA and the framebuffer above 1 GiB are not tested here. Test 532 covers the network.

- Pi 400, network boot from `/srv/tftp/pi400/`, image unchanged: row 501's `v0.6.0-dev-105-gbef6d90a+xcf2a`. No person, no power cycle. Both boots came from `reboot` typed on the console, and U-Boot loaded the image on the first try both times. 2026-11-20, 11:04–11:08 UTC.
- **Change:** the line `total_mem=1024` was removed from `/srv/tftp/pi400-fw/config.txt`, nothing else. Then the saved file was put back (`cmp` same).
