Notes from the test agent, unchecked against the code, assuming the usual cprman layouts:
- **PLLH:** CTRL `0002104D` is NDIV 77, PDIV 1, out of reset, and FRAC `58000` is 0.34375. With the 19.2 MHz crystal that gives 77.34375 × 19.2 = **1485 MHz**. In CM_LOCK `1414`, bit 12 (FLOCKH) is now set; in row 429 it was `0404`.
- **HSM:** CM_HSMCTL `295` is source 5, enabled, busy, divider `30E0`.
- The hang comes right after the HSM clock goes on. That is where the code would first touch the HDMI core, or set DVI mode. `hdmistat` deliberately does not read the core while HSM is off, so a bus hang on the first HDMI core access fits. Perhaps the core is still held in reset, or its clock is not running yet even though BUSY is set.
