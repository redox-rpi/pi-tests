# Test 566 – empty USB root port after a warm reboot, v2 (#576, PR #603)

Date: 2026-11-21, 15:40–17:11 UTC. Pi test agent. Image C `v0.6.0-dev-124-gc1155a22+xa91e` (`sha256sum -c SHA256SUMS` OK). Baseline: Test 564 A.

Result: **fail.** 18/30 boots had devsh within 120 s (564 A: 18/30).
- 11 boots had no hub after v2's port reset and power cycle: 10 empty, 1 Full speed.
- Boot 2 is not a real sample (see below).
- No `RELIBC PANIC`, no `UNHANDLED EXCEPTION`.

## The `at start` line: the same in every boot

All 29 boots that reached dwc2d logged exactly the same line, the good boots and the bad ones ([566/atstart.txt](566/atstart.txt)):

```
dwc2d: at start HPRT0 0x100d PCGCCTL 0x0
```

Decoded:
- HPRT0 0x100d = port power (bit 12), port enabled (bit 2), connect detected (bit 1), connect status (bit 0), enable change (bit 3).
- Port reset (bit 8) is **not** set. Speed bits = 0 (High speed).

So when dwc2d starts, the hub is connected and the port is enabled, **in every boot, also in the ones that end empty**. U-Boot does not hand over with the port held in reset on this Pi (QEMU showed `0x2110d`). The port state is lost later, during dwc2d's own init, between this line and the connect wait.

- Failed boots: 1, 6, 7, 8, 13, 14, 15, 17, 19, 23, 25. Without boot 2 the score is 18/29.
- **Empty boots** all have the same three lines:
  ```
  dwc2d: root port empty: Timeout("device connect"), HPRT0 0x1000 GUSBCFG 0x20001400 GOTGCTL 0x1c0000 PCGCCTL 0x0 GINTSTS 0x54000029; port reset (1/2)
  dwc2d: root port empty: Timeout("device connect"), HPRT0 0x1000 GUSBCFG 0x20001400 GOTGCTL 0x1c0000 PCGCCTL 0x0 GINTSTS 0x54000029; port power off and on (2/2)
  dwc2d: nothing on the root port, HPRT0 0x1000 GUSBCFG 0x20001400 GOTGCTL 0x1c0000 PCGCCTL 0x0 GINTSTS 0x54000029
  ```
- **Boot 6, the Full-speed mode:** `device on root port, Full speed` 3× per try, then:
  ```
  dwc2d: root port failed: Transfer(130), HPRT0 0x2140f GUSBCFG 0x20001400 GOTGCTL 0x1c0000 PCGCCTL 0x0 GINTSTS 0x55000029; port reset (1/2)
  dwc2d: root port failed: Transfer(130), … GINTSTS 0x55000029; port power off and on (2/2)
  ```
  After that, enumeration failed. HPRT0 0x2140f means a device is connected and enabled, but speed = 1 (Full).
- **Boot 2:** the recovery of boot 1 had a serial reboot, then a second serial reboot, then a plug power cycle at 15:52. **All three also came up empty**, the cold boot included. So the Pi had no network, and boot 2's devsh `reboot` never reached it. The next serial reboot (15:59) found the hub.

## Recovery

- Serial `reboot` (twice if needed), with plug power cycles at 15:52 and 16:20.
- Stable `v0.6.0-dev-115-gb972ccfd+x2d42` was staged again. Its first boot also had no devsh (17:06), and a serial reboot fixed it (17:11). devsh is up.
