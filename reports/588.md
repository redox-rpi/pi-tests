# Test 588 – pkg-persist: downloads off the RAM root, clear refusal when the copies don't fit (PR #645), Pi 3B+

Date: 2026-11-23, 20:13–20:21 UTC. Pi test agent, no person. The user's go-ahead came through the Lead. Image `~/redox-rpi-audio/keep/pkgfix-stage/` (harddrive.img.gz `e040a2e2…`, manifest `934efb56…`, both checked), build `v0.7.0-dev-22-gd598920a+x7c97`. There was no `/scheme/data/pkg` at the start.

Result: **fail.** A new error stops both installs within 2 seconds, right after the first package is downloaded:
`error: IO error: Cross-device link (os error 18), Renaming "/scheme/data/pkg/tmp/pkg_download/<pkg>.pkgar"`.
The download now goes to the data partition, as PR #645 intends. But pkg then *renames* the file to a place on a different file system (most likely its cache or install tree under `/`), and a rename cannot cross file systems (EXDEV). It needs a copy and delete instead. nano was not installed, and the space refusal in step 3 was never reached.
