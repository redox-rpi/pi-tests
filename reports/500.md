# 500: 3B+ regression for PR #548: HDMI sound on VC4 with main + `hdmi-audio` (#543)

**Result: pass on everything except one value: `dreq` is `150994961`, not `17` as in Test 418.** In hex that is `0x09000011`: the low byte is 17 (the right DREQ), but the top byte is `0x09`. The Pi 400 in Test 498 showed the same kind of value (`1106903050` = `0x41fa000a`, low byte 10). Sound works anyway, so the DMA probably uses only the low bits. But the value read from the devicetree carries extra bits since #548.
