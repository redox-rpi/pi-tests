## Reading (a guess for the audio session)

The FIFO does ask for data, DMA works, and there are no underflows, so the HSM clock and `MAI_SMP` are basically fine. The rate is wrong after the driver's own correction:
- Before the correction it measured 38544 frames/s, which is 12.6 % slow (44100 / 38544 = 1.144).
- After "correcting" it runs at 49078 to 50041 frames/s, about 11 to 13 % fast. 49078 / 38544 = 1.27, which is about 1.144². That looks as if the HSM ratio (163.68 / 143.06 = 1.144) was applied in the wrong direction, or applied twice. The measured rate also keeps creeping up over time (49078 → 50041 in 60 s).
- `no pixel clock from rpi-firmwared` means the 148.5 MHz value is assumed. If the real pixel clock differs (the NanoKVM's mode), N/CTS will be wrong as well.
