# Test 637 – Pi 400 USB idle CPU with and without #715 (measurements)

Date: 2026-11-25, 00:36–00:44 UTC. Pi test agent. Pi 400, network boot, no person. config.txt as in Test 604, restored afterwards byte-for-byte. Both payloads were used read-only.

USB devices, the same in both runs (from the boot log):
- **USB Optical Mouse** on hub port 1.1 (interface 0)
- **Raspberry Pi Internal Keyboard** on hub port 1.4 (interfaces 0 and 1)

Result: **pass.** Both runs give the numbers. No watchdog reset, no panic, no UNHANDLED.

**Method:** as in Test 636. Log in as root on the console, wait 60 s without input. Then three samples, 10 s apart, each `ps` twice about 10–15 s apart. The growth of `ACTTIME`, summed over threads, gives % of one core.

| Sample | Run A: with #715 (`keep/um4-netboot/`, `v0.7.0-dev-57-gbf62e961+xc085`) | Run B: without #715 (`keep/gfx-g3j-netboot/`, `v0.7.0-dev-73-ge4dd3340+x719b`) |
|---|---|---|
| idle 1 | usbhidd **9.2 %**, xhcid **4.1 %**, usbhubd 0.1 % | usbhidd **11.4 %**, xhcid **7.5 %**, usbhubd 0.1 % |
| idle 2 | usbhidd **6.5 %**, xhcid **2.8 %**, usbhubd 0.1 % | usbhidd **14.9 %**, xhcid **10.8 %**, usbhubd 0.1 % |
| idle 3 | usbhidd **10.5 %**, xhcid **4.0 %**, usbhubd 0.1 % | usbhidd **12.5 %**, xhcid **9.0 %**, usbhubd 0.1 % |
| **sum usbhidd + xhcid** | **9–15 %** of a core | **19–26 %** of a core |
| top others | redoxfs 0.3–0.5 %, netstack 0.2–0.4 %, rpi-firmwared 0.3 % | redoxfs 0.3–0.4 %, rpi-firmwared 0.2–0.3 %, netstack/bcmgenetd 0.2–0.3 % |
| (2) `pointer-bench 10 --hz 60` | **skipped**: this image has no `pointer-bench` (`ls: cannot access '/usr/bin/pointer-bench'`) | `600 moves in 10.0 s (60.0/s)`; during it: usbhidd **21.8 %**, xhcid 8.9 %, usbhubd 0.0 %; others redoxfs 0.5 %, fbcond 0.5 %, rpi-firmwared 0.4 % |

## What to read from it

- **With #715, the USB drivers use about half as much CPU at idle.**
  - xhcid falls from 7.5–10.8 % to 2.8–4.1 %.
  - usbhidd falls from 11.4–14.9 % to 6.5–10.5 %.
  - Together that is roughly 11–14 % instead of 19–26 % of a core.
- Even with #715, usbhidd at idle still takes 6.5–10.5 %. Something keeps it busy with no input (three usbhidd processes for the mouse and the keyboard's two interfaces).
- Run B, step 2: `pointer-bench` injects its moves through inputd, not through the USB mouse. Still, usbhidd rose to 21.8 % in that sample. That may be noise between samples (idle already ranged 11–15 %).
- Run B's idle numbers (19–26 %) agree with Test 636's (about 21–28 % at idle with the same image).
