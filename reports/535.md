# 535: Pi 400 with all 4 GiB, GENET and rpi-fb, without (A) and with (B) the DMA zone (#299, PR #580)

**Result: with all 4 GiB, GENET works in both boots.**
- DHCP and devsh come up.
- pi-test's tcp check moves 10 MiB with the right SHA-256, at **3.6 MiB/s (A)** and **3.7 MiB/s (B)**.
- 300 program starts with 0 failures.
- No panic and no `UNHANDLED`.
- **B** prints `DMA zone: 65536 KiB below 0x40000000`, and `free` shows about 63 MB more used than A.
- So I see no difference between A and B in what works.

**What fails is the same in A and B, and none of it looks like a 4 GiB effect:**
- **rpi-fb:** `no framebuffer: 1024x768: no answer from the firmware`, so `fbshot` has nothing to read. There is no monitor on the Pi 400 and no forced hotplug in `config.txt`. Row 531 shows the same with 1 GiB.
- **pi-test `sdcard`:** `/scheme/data` is missing, because there is no card in the slot.
- **pi-test `audio`:** `/scheme/audio` is missing, and audiod is not in these images.
- **pi-test `time`:** no NTP answer yet.
- **pi-test `reboot`:** devsh did not answer within 120 s. After the reboot, U-Boot's TFTP load failed and the Pi 400 sat at the U-Boot prompt (#394). Typing `boot` brought it back to login both times.
- **iperf** is not in the images (`which iperf3 iperf` finds nothing).

**Not covered:** a framebuffer above 1 GiB (needs a monitor, or `hdmi_force_hotplug`), and a long transfer. pi-test's tcp check is only 10 MiB.

- Pi 400, network boot from `/srv/tftp/pi400/`, no person, no power cycle. All boots came from `reboot` typed on the console, or `boot` typed at U-Boot after a failed TFTP load. 2026-11-20, 11:23–11:56 UTC.
- A: `~/redox-rpi-pi400/keep/genet-4g-stage/`, build `v0.6.0-dev-129-g6104c383+x6f4b` (pi400 + rpi-fb).
- B: `keep/genet-4g-mem-stage/`, build `v0.6.0-dev-129-g6104c383+x6a0a` (pi400 + rpi-fb + pi400-mem).
- Both payloads: `sha256sum -c SHA256SUMS` all OK.
- **Change:** only `total_mem=1024` was removed from `/srv/tftp/pi400-fw/config.txt`. Afterwards the saved file was put back.
- **Run 1 (11:23–11:41) ran A only:**
  - pi-test's reboot check left the Pi 400 at U-Boot before fbshot ran.
  - The script then typed `reboot` at the U-Boot prompt, which has no such command, so B and the restore did not boot.
  - I typed `boot` and repeated A and B, with fbshot first and a U-Boot recovery after pi-test. That repeat is run 2, below.
  - Run 1's A gave the same pi-test results as run 2's A.
