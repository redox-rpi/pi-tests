## Why steps 2–4 did not run

- U-Boot itself uses the Ethernet for the network boot (`eth0: ethernet@7d580000`, DHCP bound), but under Redox there is no driver for it: experiments `cosmic-apps-source desktop netstack-watch orbital orbital-apps pi400 pi400-mem pointer-bench vc4d`, without bcmgenetd. The boot log shows `smolnetd: no network adapter yet` and no `DHCP:` line. `devshd: listening on port 2323` runs, but nothing reaches it.
- My script waited for devsh for about 2 minutes, then skipped the steps and restored the Pi 400.
- Ways to run the row: build the image with bcmgenetd (the Pi 400's network driver; it came with #382), or put a USB Ethernet adapter that Redox supports on the Pi 400. Steps 3 and 4 could also run over the serial console (pointer-bench and its `vc4d: vblank:` lines), but the screenshots and `desktop-check.py` need the network to fetch the pictures.
- For the planned person test on this image: without the network there is no devsh, so the Pi test agent cannot prepare or check anything over devsh during it. The person works on the screen and keyboard only.
