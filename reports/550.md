# 550: V3D step 0 again, v3dprobe asks the firmware for power (Pi 400)

**Result: fail, safely.** The firmware answers "on", but `PM_GRAFX` stays `0x00001000` (power up false, power ok false, V3D reset asserted). v3dprobe ends with `FAIL: GRAFX still has no power after v3d_power on: V3D power off again` and never touches V3D. No panic, the Pi kept answering, and the display still runs.

- Pi 400, network boot, no person. 2026-11-20, 16:48–16:53 UTC.
- Image `keep/gfx-v3dprobe2-netboot/` (img.gz `ed88c007…`, manifest `5c128ada…`), banner `v0.6.0-dev-167-g1a57079c+xa6ac (netboot)`.
- config.txt as Test 547 (`total_mem=1024` removed, `hdmi_force_hotplug=1`, `hdmi_drive=2`).

## Steps

| Step | Result |
|---|---|
| (1) `cat v3d_power` | `off` (as expected) |
| (2) `v3dprobe` | PM_GRAFX `0x00001000` → asks `v3d_power = on` → PM_GRAFX polled 12×, always `0x00001000` → FAIL, power off again |
| (3) `cat v3d_power` | **`off`**, expected `on` (v3dprobe switched it off again after the FAIL). Took 5.1 s. |
| (4) `v3dprobe --off`, `cat`, `v3dprobe` | the same FAIL both times; `cat` gives `off` |
| (5) `vc4shot /tmp/s.ppm` | works: 640x480, 1 plane, 921615 bytes |

Other values read, the same each time:
- devicetree `v3d@7ec04000 (brcm,2711-v3d)` status disabled;
- bridge id `0x62726467` = "brdg";
- `ASB_V3D_M_CTRL` 7 and `S_CTRL` 7;
- clock v3d 250 MHz (max 500).

**rpi-firmwared on serial:** the mailbox says yes each time:

```
rpi-firmwared: V3D power on, firmware says Some(true)
rpi-firmwared: V3D power off, firmware says Some(false)
```

These two lines came three times, once per v3dprobe run. 0 lines with `panic` or `UNHANDLED`.

So the firmware reports domain 10 as on, but the PM_GRAFX register does not change. Either the firmware does not switch the domain through PM_GRAFX on the BCM2711, or the check reads the wrong register for this chip. The ASB bridge controls (M/S_CTRL = 7, meaning stopped) did not change either.
