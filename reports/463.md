- **Client ports change every boot** (e.g. 49961/49963 in boot 1, 51502–51505 in boot 2, 52942–52946 in boot 3, 60329/60333 in boot 5, … 56353 in boot 20). Before the patch, the five connections the server held from the boot before the series all came from 50691–50701.
- **The server never closes connections from boots that are gone.** Up to 17 at once (ESTAB, FIN-WAIT-1, CLOSE-WAIT). Typically the connection of a failed HTTP try stays ESTAB with 150–455 KB in the send queue that nobody will ever ACK. At the end of the run the server still held 17. The server is `/usr/bin/python3 -m http.server 8080 --directory /srv/tftp` (one thread per connection, 13 threads when I looked, up 2 days 7 h), so a stuck connection holds a thread but doesn't block new ones.
- The failures look as before: each HTTP try `HTTP client error 5`, each TFTP try `Loading: Timeout!`. The new connection of a failed HTTP try is accepted by the server (ESTAB) and has data queued, so the server did send; U-Boot then gave up on it.
