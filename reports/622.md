## The USB mouse and usbhubd (not U-Boot)

The user plugged a USB mouse into the Pi 400 at 19:44 UTC, so that it stays there. The mouse was in for all 20 counted boots.

- In **every** boot with row 501's image, Redox's `usbhubd` panics on it:
  - `xhcid: Failed to address device at slot 2 (port 1.1), completion code 0x4`
  - `usbhubd main.rs:136: Failed to attach: IoError(… I/O error)`
  - then an `UNHANDLED EXCEPTION` in `/usr/lib/drivers/usbhubd`
- The boot still reaches the login. The fix belongs to Graphics' #710/#711 work (row 623).
- **Try 1** (19:43–19:47) stopped at boot 3 because of this panic. The script took the `UNHANDLED EXCEPTION` for a failed boot and put the old U-Boot back, although U-Boot was clean in all 3 boots ([try1/](622/try1/)).
- **Try 2** judged only the U-Boot side and counted the Redox USB fault separately (`usbfault` column: 1 in each boot).

Afterwards: new U-Boot kept, row 501's image at the login. lab.md updated (Pi 400 row).
