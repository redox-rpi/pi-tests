# 537: why the 200 MiB TCP check fails its SHA-256 on the Pi 400 (follow-up to Test 536)

**Result: it is the free space in `/tmp`, not the network and not memory.**
- `/tmp` is on the root file system of the network-boot image, the 256 MB live disk, and that has **114472 KiB free**.
- With 200 MiB, `nc` stops at about 116 MB with `nc error: Error occurred while writing into stdout: No space left on device (os error 28)`. The hash then cannot match.
- The same 200 MiB into `/scheme/null` arrives completely, twice: the host sent all 209715200 bytes in 16.8 s.
- 100 MiB into `/tmp` is complete: 104857635 bytes = 100 MiB + the 35-byte `Remote host: …` line that Redox's nc writes first. `check_tcp` accepts that line.

**For the check:** `pi-test.py`/`regression-set.py` `--tcp-mib` above about 110 cannot work on a network-boot image while the file goes to `/tmp`.
- Either hash on the Pi without a file (e.g. `nc … | sha256sum`), or keep `--tcp-mib` at 100.
- So the 200 MiB FAILs in Test 536 say nothing about the 4 GiB or the DMA zone.

- Pi 400, network boot, normal `config.txt` (1 GiB), no person, no power cycle. Image `~/redox-rpi-pi400/keep/genet-4g-stage/` (`v0.6.0-dev-129-g6104c383+x6f4b`). 2026-11-20, 12:19–12:25 UTC.
