# Test 605 – first Pi run of the nightly TinyCC VC4 track's Pi part (PR #412, #410), Pi 3B+

Date: 2026-11-24, 11:30–11:50 UTC. Pi test agent, no person, no card write. From the owner's clone `~/rbc-build/tcc-track-412/redox-rpi` (`tcc-track` ab48a5b9):
`scripts/tcc-track-pi.py --g ../out/G.bin --t ../out/T.bin --out ../out/pi.json --rbc-load ../work/rpi-open-firmware/bootcode/rbc-load.sh`.
G.bin 14584 B (`4c37b297…`), T.bin 21636 B (`b7d013eb…`), both checked. Before running, I read the script: it only reads from the card (`sd`, `fl`, `crc`, `ls`, `sdr`), writes to the serial port without reading it (replies come from the serial log), and never switches power. Its `rbc-load.sh` differs from the lab copy only in the default TTY, and the script passes the TTY from lab.env.

Result: **pass for the row's checks.** Exit 0, `"pi_pass": true`, `"pi_back": true`, `diff` empty, `fl_g_s` 3.71 and `fl_t_s` 4.21, and `redox login:` afterwards. **But the stable image then came up without USB** (#576): devsh did not answer, and it took 2 serial resets, a power cycle with a 12 s pause, one more serial reset, and finally a **power cycle with a 30 s pause**.

## After the run: no USB on stable

- `pi_back` only checks for `redox login:`. That boot had `dwc2d: nothing on the root port`, so no network and no devsh: the #576 warm-reboot fault, since stable does not have `usb-port-power`.
- My recovery: 2 serial resets, a Shelly power cycle (12 s off), and one more serial reset all still gave `nothing on the root port`. **A power cycle with 30 s off** brought `device on root port, High speed` and devsh (11:50). A 12 s power cycle not being enough is new: until now a power cycle always cleared #576.
- For the nightly track: after the Pi part, a check that devsh answers (not only `redox login:`) would catch this. As long as stable lacks `usb-port-power`, expect to need a serial reset or a power cycle after the track.

Afterwards: stable `v0.7.0-dev-9-g368175ee+x2d42` booted, devsh up (11:50).
