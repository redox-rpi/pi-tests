**Method (changed twice today, agreed with Network).** netget is no longer
built, and stable has neither curl nor wget, so each download is an
HTTP/1.0 GET through the Pi's `nc` from the serial console as root:

```
ion -c 'echo -e "GET /models/Qwen3-0.6B-Q4_0.gguf HTTP/1.0\n"; sleep 600' | nc 192.168.178.120:8080 > /scheme/data/dl.bin
```

- **nc's quirks:** this nc takes `host:port`, and it exits only when its input closes. So the input stays open for 600 s, and a download's real time comes from the file size.
- **Size readings:** homenodellm read the size over devsh every 10 s. Those readings are also the outside probe: homenodellm has no `ping` binary.
- **Checks afterwards:** `ls -l`, then `tail -c 382156480 dl.bin | sha256sum` against `33bcc570…f75cb`. The complete file is 382156721 bytes: nc's `Remote host:` line, then the HTTP header, then the body.
- **In a stall:** wait 2 minutes, check devsh, send Ctrl-C, then run the readings below, one `grep` each, because the Pi's grep takes one pattern.
- **Readings:** `echo hi`, `ls -l /scheme/data`, `ps`, then the context entries for netstack, dwc2d, inputd and redoxfs.
- **Recovery:** a serial `reboot`, and a power cycle when that does not reach `redox login:` within 90 s.

Attached: the NanoKVM only (USB keyboard and absolute mouse, `mouse at
address 3`; LAN7800 at address 4).
