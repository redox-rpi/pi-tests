# 487: Direct SD card with U-Boot fallback (PR #546), Pi 3B+

**Result: blocked by the card, as the row allows. Nothing was booted or changed.** The test Pi's card has a FAT boot partition of 63 MiB. The row's `initramfs` is 260 038 656 bytes (248 MiB), so it does not fit, about four times too big.

- **The test Pi's card** (the boot selector card, SC16G), from `part list mmc 2` in U-Boot (recorded in Test 466):

  | Part | Start sector | Sectors | Size | Type |
  |---|---|---|---|---|
  | 1 | 2048 | 129 024 | 66.1 MB (63 MiB) | 0c FAT32, boot |
  | 2 | 131 072 | 1 966 080 | 1.0 GB | da |

- **Used on partition 1:** the 24 root files total 5 262 998 bytes (bootcode.bin, start.elf, start_cd.elf, u-boot.bin, the three dtbs, the selector images and so on), plus `overlays/` with two small dtbo files. Free is therefore about **60 MB**, minus FAT overhead (Tests 466–468 wrote up to 51 MB there).
- **Needed:** `initramfs` 260 038 656 bytes + `kernel8.img` 1 953 792 + `u-boot.bin` 958 968 + small files, about 263 MB.
- **Flashing the whole card** (`sdcard-direct-fb.img.xz`) is not possible without a person: it would replace the boot selector card, which the remote setup depends on, and only a person can swap cards back.
- Payload as given: `~/redox-rpi-pi400/keep/direct-fb-487/` (not moved or changed).

The row can run when it has a card with a FAT partition of at least about 300 MB:
- either a second card that a person swaps in (like row 427's 64 MB card visit), with `sdcard-direct-fb.img.xz` written to it;
- or the selector card re-partitioned with a bigger first partition (person task).

The 3B+ was not touched and stays on stable.
