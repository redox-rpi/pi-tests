# 496: does the VPU stay alive in the selector's halt? (rof #40 / PR #52, diagnosis for the Test 495 wake)

**Result: yes, the VPU stays alive and keeps polling.** `halt-diag: clocks switched` came right after the `halt:` line. Then a heartbeat came every 10 s: **7 heartbeats in the 70 s captured** (the row expected 6 in 60 s). GP_LEV0 read **`0000C1FF`** every time, so **bit 3 (GPIO3) is 1**, as expected with the pull-up. The Shelly read 0.0 W the whole time, so the plug can't see the VPU's idle draw.

- Pi 3B+, selector card with 56354b8, nothing written to the card, no person. 2026-11-17, 19:58–20:01 UTC.
- Payload `~/rbc-build/payloads/sel-20261117a/bootcode-selector-haltdiag-20261117b.bin`: 61560 bytes, sha256 `61749bab01f8…` (matches the row), crc32 `76FA101F`.
- Steps:
  - Shelly power cycle.
  - Cold start with Enter: `rbc-load.sh --enter` gave `ok monitor` from the card's 56354b8.
  - The file was loaded to c1000000, then `w 7e100020 5a000555`, then `chain c1000000 f078` (`ok chain 61560 bytes`, banner `redox-rpi bootcode 44ab1cf (M1, monitor, test build, boot selector)`).
  - Serial captured with times (`tsl.py`) for 80 s.
  - Shelly power cycle back to stable.
