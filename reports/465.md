# 465: #394 Pi 400 U-Boot RGMII delays as in Linux (PR #465 c8f05907)

**Result: pass, 20 of 20.** With the new files, all 20 serial reboots reached `redox login:` without a manual `boot`, **with no retry at all**: no failed DHCP try and no failed load in any boot. The image loaded over HTTP in **776–810 ms** every time (median about 802 ms; rows 461/463: median 2.3–2.4 s, max 22–43 s). The register that changed is the MAC's: EXT_RGMII_OOB_CTRL (0xfd58008c) goes from `00f10050` (bit 16 set, MAC TX delay off) to **`00f00050`** (bit 16 clear, MAC TX delay on).

**About the PHY (as found, for the analysis):** the PHY is at **MDIO address 0** on `mdio@e14`, not 1. Its ID is **`0022 1642`**, not the BCM54213PE's `600d 84a2`. U-Boot binds the **`Generic PHY`** driver to it with both the old and the new files, so the Broadcom PHY driver (`CONFIG_PHY_BROADCOM=y`) doesn't take it. The fix that worked is therefore the MAC TX delay, not a PHY setting.

### Extra boots for Architect (after B, with old and new files)

Architect asked for `mdio list`, `mii device <GENET bus>` and the reads, once with each set of files. `mdio list` gives in both cases:

```
mdio@e14:
0 - Generic PHY <--> ethernet@7d580000
```

So I ran the reads twice per set of files: at address 1 as asked, and at address 0, where `mdio list` puts the PHY.

| | address 1: reg 2 / 3 / 0x18 / 0x1c | address 0: reg 2 / 3 | address 0: 0x18 after writing 0x7007 / 0x1c after writing 0x0c00 | 0xfd58008c |
|---|---|---|---|---|
| old files | FFFF / FFFF / FFFF / FFFF | **0022 / 1642** | 7007 / 0C00 | `00f10050` |
| new files | FFFF / FFFF / FFFF / FFFF | **0022 / 1642** | 7007 / 0C00 | `00f00050` |

At address 0, registers 0x18 and 0x1c read back exactly the value just written, in both cases. On this PHY they don't seem to behave as Broadcom shadow registers, so they say nothing about RX skew or PHY TX delay. The ID 0x0022/0x1642 is in the Micrel/Microchip range, my reading, not checked. `mii info`'s OUI 0x0885 / Model 0x24 is the same PHY, decoded by U-Boot; it also shows up at address 4.
