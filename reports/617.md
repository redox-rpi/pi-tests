## Finding: leftover child of the failed fork

`ps | wc -l` went from 53 to 63. In the final `ps` ([psfull.txt](617/psfull.txt)):
- **`395 … KB ? … 65.0 KB … /usr/bin/oomtest`**: step (2) ran as PID 394, so 395 is the child the failed fork started to build. It is still listed at the end, blocked, with no CPU.
- Three `login` + `ion` pairs and more `devshd` threads. These come from the devsh sessions: stable does the same (checked right after on stable: two `login`/`ion` pairs left after four devsh commands). They are not from this test.

So the kernel returns ENOMEM correctly, but the half-made child context does not seem to be cleaned up. It only holds 65 KB, so it does not matter for memory, but each failed fork would leave one more entry. Quality may want to check it.
