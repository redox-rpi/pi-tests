A note from the test agent, unchecked against the code: if CTRL uses the usual cprman layout (NDIV in bits 0–9, PDIV in 12–14, PWRDN 16, PRSTN 17), then `00020001` reads back as **NDIV 1, PDIV 0**, out of reset. That looks as if the divider write did not reach the register, for example a missing 0x5A password or the wrong offset. Or the read comes from somewhere else. In CM_LOCK `00000404`, bit 12 (FLOCKH, if that layout holds) is clear.
